# Infrastructure (`infra/`)

Terraform, organized as reusable modules plus one directory per environment.

- **`infra/modules/lambda`** — Lambda function, IAM role/policies (DynamoDB item access, SNS publish, SES send, SSM read), CloudWatch log group.
- **`infra/modules/api_gateway`** — HTTP API (API Gateway v2), a single `$default` stage (no path prefix required — see note below), catch-all `$default` route to the Lambda, optional access logging.
- **`infra/modules/dynamodb`** — the seven DynamoDB tables (pay-per-request), with TTL attributes where relevant.
- **`infra/modules/sns`** — SNS topic used for SMS OTP delivery.
- **`infra/modules/ssm`** — SSM Parameter Store entries for JWT secrets, encryption keys, cookie secrets, the OIDC JWKS signing key (RSA private key PEM, via `tls_private_key`), issuer name, support email (all secrets are randomly generated by Terraform, never hand-set, and persisted across deploys so tokens signed with them keep validating).
- **`infra/modules/website`** — S3 bucket (private, CloudFront-OAI-only) + CloudFront distribution with two behaviors: default (SPA, with a CloudFront Function for SPA-style routing) and `/api/*` (proxied to API Gateway, no caching).
- **`infra/environments/local`** — wires the modules together against **Ministack** (a local AWS emulator), used for local dev.
- **`infra/environments/production`** — wires the modules together against real AWS, plus ACM certificate + validation for the custom domain.

> **Note on API Gateway stage naming:** the HTTP API stage **must** be named `$default`. Any other stage name requires the stage name as a URL path prefix to be reachable — CloudFront's origin config here does not add one, so a non-`$default` stage will 403 every request routed through CloudFront.
